\section{Introducción}

En las actividades anteriores se trabajó con MongoDB, una base de datos de documentos. En este proyecto se usó una base de datos de grafos, Neo4j, en la que los datos se guardan como nodos y las relaciones entre ellos se almacenan explícitamente. Se desarrolló una aplicación en Python con interfaz gráfica que administra un blog: usuarios, artículos, comentarios, tags y categorías, con las relaciones del modelo indicado en la actividad. La aplicación permite crear, consultar, modificar y eliminar cada tipo de nodo, y realizar consultas que recorren el grafo.

El código de la aplicación y los archivos Cypher se encuentran en el repositorio \url{https://github.com/LF-Dguez/blog_neo4j}.

% ============================================================
\section{Objetivo}

Desarrollar una aplicación de base de datos de grafos.

\section{Entorno de trabajo}

El proyecto se realizó en Windows 11 con Neo4j Desktop 2 y una instancia local de Neo4j 2026.10, a la que la aplicación se conecta por el protocolo Bolt en \texttt{localhost:7687}. La aplicación se escribió en Python 3.14 con el driver oficial de Neo4j (paquete \texttt{neo4j}) y la interfaz con Tkinter, que viene incluido en Python.

\section{Modelo de datos del blog}

El modelo de la actividad tiene cinco tipos de entidad. En Neo4j cada una es una etiqueta de nodo, y cada relación del diagrama es un tipo de relación con dirección:

\begin{lstlisting}[style=plainStyle]
(:User {id, name, email})
(:Article {id, title, date, text})
(:Comment {id, name, url, text, date})
(:Tag {id, name, url})
(:Category {id, name, url})

(:User)-[:WROTE]->(:Article)            1 a N
(:User)-[:POSTED]->(:Comment)           1 a N
(:Article)-[:HAS_COMMENT]->(:Comment)   1 a N
(:Article)-[:TAGGED_WITH]->(:Tag)       N a N
(:Article)-[:IN_CATEGORY]->(:Category)  N a N
\end{lstlisting}

Las decisiones principales del modelo fueron las siguientes:

\begin{itemize}[itemsep=2pt, topsep=4pt]
    \item Cada nodo tiene una propiedad \texttt{id} generada con \texttt{randomUUID()}. La aplicación busca, modifica y elimina siempre por ese identificador.
    \item Las relaciones N a N no necesitan una tabla intermedia como en una base relacional: un artículo se conecta directamente con cada uno de sus tags y categorías.
    \item En el diagrama, los comentarios tienen las propiedades name y url. Se interpretaron como el título corto del comentario y su enlace permanente, y se agregaron text, con el contenido, y date. La url la genera la aplicación a partir del título del artículo.
    \item Las fechas de artículos y comentarios se guardan con el tipo \texttt{date} de Neo4j.
    \item Al eliminar, un usuario que tiene artículos o comentarios no se puede borrar; un artículo se elimina junto con sus comentarios; un tag, una categoría o un comentario se eliminan junto con sus relaciones.
\end{itemize}

\subsection{Restricciones de unicidad}

Cada \texttt{id} es único, igual que el email de un usuario y el nombre de un tag o de una categoría. Una restricción \texttt{UNIQUE} también crea un índice, así que las búsquedas por esas propiedades son rápidas.

\codigo{cypherStyle}{../cypher/01_restricciones.cypher}

\subsection{Datos iniciales}

El archivo \texttt{02\_datos.cypher} borra los nodos del blog y vuelve a crear 5 usuarios, 4 categorías, 8 tags, 8 artículos y 14 comentarios con todas sus relaciones. Se usa \texttt{UNWIND} para crear varios nodos a partir de una lista en una sola sentencia.

\codigo{cypherStyle}{../cypher/02_datos.cypher}

\subsection{Cargador de archivos Cypher}

\texttt{cargar\_cypher.py} ejecuta en orden las sentencias de uno o varios archivos \texttt{.cypher}. De cada una muestra su título (el comentario que tiene arriba), lo que cambió en la base y, si tiene \texttt{RETURN}, sus primeras filas. Al final cuenta los nodos y las relaciones del blog.

\begin{lstlisting}[style=plainStyle]
python app/cargar_cypher.py cypher/01_restricciones.cypher cypher/02_datos.cypher
\end{lstlisting}

\section{Conexión y ventana principal}

\subsection{Conexión con Neo4j}

La clase \texttt{BaseDatos} lee \texttt{config.ini}, crea el driver de Neo4j y ofrece tres métodos: \texttt{consultar} para lecturas, \texttt{ejecutar} para escrituras y \texttt{transaccion} para varias sentencias que deben aplicarse juntas. Los valores siempre se envían como parámetros (\texttt{\$id}, \texttt{\$name}), nunca pegados al texto de la consulta, y los tipos de Neo4j como \texttt{date} se convierten a texto para mostrarlos.

\codigo{pyStyle}{../app/conexion.py}

\subsection{Componentes comunes de la interfaz}

Todas las pestañas de administración tienen la misma distribución: a la izquierda una tabla con los registros y a la derecha un formulario con los botones Nuevo, Guardar y Eliminar. Esa distribución está en la clase \texttt{PestanaCRUD}; cada pestaña hereda de ella y solo define sus columnas, sus campos y el Cypher de cada operación. Para las relaciones hay dos controles: \texttt{Selector}, una lista desplegable para elegir un nodo (por ejemplo, el autor), y \texttt{ListaMultiple}, para elegir varios (por ejemplo, los tags).

\codigo{pyStyle}{../app/ui_comun.py}

\subsection{Ventana principal}

\texttt{main.py} se conecta a la base, muestra la versión del servidor en el encabezado y agrega una pestaña por cada módulo. Al cambiar de pestaña se recargan sus datos, porque otra pestaña pudo haber creado o eliminado nodos relacionados.

\codigo{pyStyle}{../app/main.py}
